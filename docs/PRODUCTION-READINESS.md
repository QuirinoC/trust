## Concrete technical gaps and order

1. **Offline queue correctness.** The client sends ordered batches of at most 100, continues after each successful acknowledgement, and retains the failed batch and suffix for retry; the API limit remains in [`TrustEndpoints.cs`](../apps/trust-api/Api/V1/TrustEndpoints.cs). It prunes points older than 30 days or more than 120 seconds in the future. Tests cover >100 points, a failed second request, retry ordering, account scope, and stop-sharing invalidation. A request accepted by the server whose response is lost can still be replayed: add server-visible idempotent point identifiers and queue count/byte limits, and test reconnect, restart, and expired points. Move pending coordinates from plain `UserDefaults` JSON in [`LocationIngestStore.swift`](../apps/trust-ios/Sources/TrustApp/LocationIngestStore.swift) to protected local storage with an explicit deletion policy.
2. **Durable receipts and subscriptions.** A Look is stored before APNs is attempted inline, without a durable retry. Use a transactional outbox, bounded retry, invalid-token handling, and dead-letter triage. Age-consent `RESCIND_CONSENT` is signature-verified, hash-matched, and retry-idempotent; other App Store notifications still apply inline, and unknown subscription owners are logged and dropped. The age-range itself is evaluated on-device and is not verifiable by the API; if law or threat review requires server-side age enforcement, select a privacy-reviewed assertion/provider before collecting protected data. Persist and deduplicate all notification IDs, replay unknown-owner events, reconcile with the App Store Server API, and model billing retry/grace, revocation, refund, restore, and out-of-order events. A paid-but-locked account must be diagnosable without support staff reading location history.
3. **Capacity hot paths.** The circle response performs per-person queries and loads Look records to count them; history has no paging; location points are inserted one at a time; each API replica starts a global minute sweeper; entitlement sweeping scans subscriptions. Batch/aggregate reads, keyset-page history and Activity, batch/idempotently ingest points, and give one leased worker ownership of each due cleanup/reconciliation job. Keep the latest location distinct from historical trails. Distribute rate limits across replicas. Profile before choosing caches or partitions; revocation checks must use authoritative state.
4. **Bounded external spend, SMS consent, and abuse.** The global SMS budget is 40/day in the current beta configuration, not a production capacity target. Migration 021 and consent-event persistence are live in the deployed API. The current app source sends disclosure version and Send/Resend action; rebuild the release binary from `main` before claiming that behavior is present in the candidate. The public Privacy page documents storage and deletion of verification consent records, and `/sms` describes the Send-code flow. The registered Twilio campaign's current opt-in method/status and HELP/STOP behavior remain unverified against the app. Verify those before public submission; configure country, phone/account/device/IP budgets and provider spend alarms, and add an emergency stop that preserves sign-in alternatives/support. Define block/reinvite prevention, coercion and stalking reports, compromised-device session revocation, support escalation, and audited operator access. Avoid routine coordinate access in support tools.
5. **Runtime and release discipline.** Upgrade .NET 9 before its scheduled 2026-11-10 end of support. Use isolated staging credentials and data, backward-compatible migrations, versioned deploys, an explicit rollback point, and an on-call owner for each release. Validate the custom API hostname's TLS before pointing a client at it. Confirm the current TestFlight build is processed and assigned before interpreting a device test.
6. **Cross-device convergence and revocation.** The paired iPhone 17 Pro + Duo simulator E2E from 29 September passed the connection lifecycle, sharing, Look/map/Activity, Stop, removal, and re-add. That paired run predates the current branch. The current branch separately passes 81 Swift tests, 202 API/Postgres tests, and 10 age-gate simulator UI tests; the added Stop All and stale-queued-location protections are covered in that source. A paid-entitlement History race, same-account reconnect on a second device, and offline/relaunch/reconnect remain pending. Simulators do not verify physical APNs or background execution. Account-wide Home-setting semantics still need a product decision/test because Home is device-local.

## The minimum operating cockpit

The targets below are **proposed initial objectives**, not measured performance or promises to customers. Review them after a beta baseline. Dashboards should show app version, release/deploy annotations, region, traffic, and sample size; charts must not include phone numbers, coordinates, names, invite codes, raw tokens, or other sensitive payloads.

| View | Signals | Initial action threshold |
| --- | --- | --- |
| API and database | Eligible request success, endpoint p50/p95/p99, 5xx/429, latency by version, connection pool, slow queries/locks, CPU, storage, migration and health results; authenticated no-SMS synthetic flow. | Proposed 99.9% 30-day request-success SLO and 99% of core reads under 1 second server-side. Page on sustained error-budget burn corroborated by synthetics at low traffic. |
| Location and consent | Ingest accept/reject/duplicate, local backlog age/count, age of latest permitted point by mode and permission, stale/empty map reads, revocation-check failures, retention-worker lag. | Page on any confirmed post-revocation access; investigate freshness regression and a stalled sweeper. Never infer freshness from a 200 response alone. |
| Notifications and SMS | Receipt recorded/queued/APNs-accepted, oldest outbox age, retry/dead-letter and invalid-token counts, SMS provider status/cost, verification completion and time-to-verify. | Proposed 99% first APNs attempts within 60 seconds; page if oldest queued receipt exceeds 5 minutes. Alert on abnormal SMS spend or conversion drop. |
| Mobile and revenue | Crash-free sessions, hangs, network errors by build/device/iOS, battery impact; verified entitlements, purchase/restore failures, notification lag, unmatched transactions, paid-but-locked cases, renewal/churn/refunds/net proceeds. | Proposed 99.9% crash-free sessions with count shown. Page on a growing entitlement-reconciliation backlog; investigate failed release cohorts. |
| Product and care | Onboarding → accepted connection → first consented share, weekly active connected pairs, D7/D30 retention, support volume/category and response time. | Use trends to decide UX/pricing work, not as paging alerts. Retain aggregate data under a written analytics policy. |

An initial tool stack can be small: one crash reporter, one metrics/logs/traces service, uptime/paging, a shared support inbox, and managed database backup/high availability. Prefer existing Render and Cloudflare capabilities where they meet the measured need; choose one provider per capability with telemetry retention/spend limits. Keep session replay off location screens. A status page becomes useful when incidents affect real customers. Record who receives alerts **and run a drill** before relying on any dashboard.

- Document data classes and retention across app queue, API database, backups, logs, analytics, support tickets, and vendor systems. ## Product and subscription decisions

Keep the existing **individual Plus** offer simple while measuring onboarding, connected-pair retention, purchase conversion, renewals, support complaints, and net proceeds. Free consent and safety controls stay usable. A household payer might remove the friction of every sharer buying Plus, but research it before adding a second SKU: determine who pays, who retains consent, who loses access on removal/downgrade, and how Apple Family Sharing interacts with the product. Never let the payer control someone else's consent.

Do not add a subscription-management vendor or Stripe just to appear production ready: native StoreKit already exists, while web billing is disabled. Add vendors only where reconciliation, support workload, or new platform distribution justifies cost and migration. Verify hardcoded website prices and trial claims against the live App Store by territory before public launch. Track unit economics per *active connected pair*: subscription net proceeds against SMS, maps/location storage, database, network egress, APNs operations, observability, support, and refunds. Model peak active sharers and update cadence, not only registered users.

For illustration only, **100,000 active sharers × 288 points/day = 28.8 million points/day**; at 30-day retention that is **864 million points** before indexes and replicas. Neither 100,000 sharers nor 288 points/day is a current Trust measurement. Benchmark real cadence and a reconnect storm before deciding partitioning, database size, or region strategy.
