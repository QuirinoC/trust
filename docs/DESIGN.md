# Trust iOS design

## Direction

Trust uses the current native iOS interface with a cool porcelain canvas, white elevated surfaces, deep navy text, blue actions, and teal positive states. Keep the current app icon in place; app-icon redesign work is paused.

Use rounded system typography, clear hierarchy, 20–24 pt page gutters, a consistent 20 pt title inset below the safe area on non-map tabs, 16–24 pt corner radii, and controls at least 44 pt tall. The palette adapts to dark mode: navy canvas, lighter navy surfaces, readable ink, and brighter blue and teal accents. Illustration belongs mainly on the sign-in screen and in the optional profile-icon gallery. Functional screens stay quiet and native.

## Screen intent

- **Sign in:** present a modest Trust wordmark and the current motif, then a recognizable “Sign in to Trust” heading. State that sharing stays off until a mode is chosen for each person. Sign in with Apple is primary; Terms, Privacy, and Support remain reachable.
- **Handle:** explain the public handle rules, show availability feedback, and keep submission disabled for invalid or taken handles. Offer an optional profile-picture shortcut in this existing step; choosing a picture never blocks Continue and never changes sharing.
- **Phone:** use one clearly disclosed Send code action to request a one-time verification text. Show “Phone verification is required.” above the field and the one-time-text agreement, “Standard message and data rates may apply,” frequency, HELP, and STOP directly below the button. The keyboard submit action must not send a code. After sending, keep code entry and Verify visible without scrolling. Keep Privacy and Terms at the bottom. The registered Twilio 2FA campaign and public `/sms` evidence must match this flow before it ships.
- **People:** keep the map and people list together. Empty states guide people to Sharing; connected people who are not sharing remain visible. Use the shared bottom navigation for People, Sharing, Activity, and You.
- **Sharing:** keep Add someone prominent above incoming Requests, connected People, Sent requests, and secondary Home status. Add someone opens one large native sheet with Cancel, a title, and an autofocus handle field. Search performs an exact handle lookup; show one result with `@handle`, generated initials, and Send request. The helper asks people to get the handle from You. Do not offer phone, invite-code, link, or contact-book choices in this flow. Incoming requests have Accept and Decline; sent requests show Pending and Cancel. Accepted connections start with both share directions Off. Connected people keep one compact row with name on the left and Off / Sealed / Always on the right; Pause and Remove are secondary actions. Stack mode controls when width or text size requires it. Confirm Stop sharing and Remove in a centered alert with the person's name. Home / Away / Hidden remains secondary because it controls what others see. Adding someone never starts location sharing.
- **Activity:** show recorded events and receipts with their status and timing; keep the empty state calm and useful.
- **You:** focus on profile picture, a visible and copyable personal handle, membership, My location, appearance, and account. Tap the avatar with its camera badge to open the shared picture picker. Keep Terms, Privacy, and Support links fixed at the bottom of the screen. My location opens a detail screen for device permission and Home place, while sharing status controls live in Sharing. Appearance is a compact System / Light / Dark preference saved on this device, with System as the default.
- **Profile pictures:** offer 11 sleepy-animal illustrated choices in a horizontal carousel, with no visible names; expose each choice's name to accessibility. Keep the selected picture large and centered in the preview. Put Photos, Camera, and Remove picture in a native menu attached to the preview avatar; do not add a separate photo section. Use a compact sheet that can expand when needed. Stage changes until Save and disable editing while a save is running. A picture is visible only to active connected people; removing it falls back to initials. Preserve initials for missing or failed photo loads. Do not expose raw photo URLs outside authenticated API calls. The selected art direction is **hand-drawn doodle**: purposeful slightly uneven navy pen strokes, matte muted fills, subtle asymmetry, and one sleeping animal on a quiet background. Avoid redundant contours and fur hatching. Each subject must read clearly inside a 44 pt circular crop. No text, border, or glossy depth. Sleepiness is identity art and must never indicate whether someone is offline, safe, or sharing.

  The [approved sleepy-animal catalog](avatar-style-exploration/sleepy-set/index.html) shows all 11 choices at 44, 72, and 116 pt. The current animal-only catalog includes Siamese, Ragdoll, and British Shorthair cats. Keep legacy preset IDs readable for saved profiles even when the picker no longer offers them. New IDs must be accepted by the API before they are offered in the app. In the offline demo, preset edits last for the current session and photo actions are disabled with an explanation; the live app uses authenticated save behavior.
- **Plus:** use StoreKit's subscription products for price and period, preserve restore and policy links, and show purchase or restore errors clearly.

## Duo layout target

The closed Duo keeps the compact phone experience. When open, the map stays on the left and people/detail navigation stays on the right. The adaptive People layout and width-aware Map route are implemented, with one NavigationStack retained across layout changes. The Duo and iPhone 17 Pro UI suites both pass 4/4, including a check that Map keeps a useful canvas inside the detail pane. Manual Device Hub testing confirmed that the selected person remains visible through Duo close/open, with compact person detail closed and map-left/person-detail-right open.

## Product language

Sharing is a per-person choice. Avoid implying that Trust guarantees delivery of push notifications or SMS beyond the verification flow. Describe map, presence, and activity only as implemented; distinguish a one-time snapshot from live sharing.
