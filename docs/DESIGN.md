# Trust iOS design

## Direction

Trust uses warm paper, charcoal ink, muted clay-red actions, and quiet sage status colors. The illustrated sleepy-animal avatars supply the hand-drawn warmth; keep functional screens calm, spacious, and unmistakably native iOS. Carry the warm colors through light mode while keeping the established deep-navy dark mode. Keep the current app icon in place; app-icon redesign work is paused.

Use rounded system typography, clear hierarchy, 24 pt page gutters, a consistent 20 pt title inset below the safe area on non-map tabs, soft 18–24 pt corners, and controls at least 44 pt tall. Use illustration sparingly: the profile gallery and real profile pictures carry the animal art into the app. Avoid decorative symbols that could be mistaken for a person's real profile. Keep Stop, Pause, visibility, and other consent controls plain and clear.

## Screen intent

- **Sign in:** present a modest Trust wordmark and the current motif, then a recognizable “Sign in to Trust” heading. State that sharing stays off until a mode is chosen for each person. Sign in with Apple is primary; Terms, Privacy, and Support remain reachable.
- **Handle:** explain the public handle rules, show availability feedback, and keep submission disabled for invalid or taken handles. Offer an optional profile-picture shortcut and an explicit, default-off “Help people find me” choice. Continue sends discovery consent version 1 only when the person turns that choice on; changing a picture never enables discovery or changes sharing.
- **Phone:** use one clearly disclosed Send code action to request a one-time verification text. Show “Phone verification is required.” above the field and the one-time-text agreement, “Standard message and data rates may apply,” frequency, HELP, and STOP directly below the button. The keyboard submit action must not send a code. After sending, keep code entry and Verify visible without scrolling. Keep Privacy and Terms at the bottom. The registered Twilio 2FA campaign and public `/sms` evidence must match this flow before it ships.
- **People:** keep the map and people list together. Empty states guide people to Sharing; connected people who are not sharing remain visible. Use the shared bottom navigation for People, Sharing, Activity, and You.
- **Sharing:** keep Add someone prominent above incoming Requests, connected People, Sent requests, and secondary Home status. Add someone opens one native sheet with a compact close control, “Find your person” heading, a single reassurance that sharing stays off until chosen, and an autofocus “Handle or phone number” field. Search automatically after 350 ms using an exact handle or complete phone number with the device region or explicit country prefix; there is no Search button. Keep the sheet visually light: one compact bordered field, no duplicate guidance or decorative card shadows, and a simple result row with the opted-in picture and `@handle`. Put Send request in a clear full-width action. For a valid phone search with no eligible match, show a plain no-match state and “Share invite link.” This wording describes the action without claiming the number is not registered: phone discovery is opt-in. Tapping opens native sharing; only then is the legacy invite link created, and dismissing the share sheet does not mean it was sent. Do not offer an address book, invite-code entry, or an automatic Trust-sent text. Preserve the current TestFlight install-and-reopen path for a recipient without the app; do not invent a public store URL. Incoming requests have Accept and Decline; sent requests show Pending and Cancel. Accepted connections start with both share directions Off. Connected people keep one compact row with name on the left and Off / Sealed / Always on the right; Pause and Remove are secondary actions. Stack mode controls when width or text size requires it. Confirm Stop sharing and Remove in a centered alert with the person's name. Home / Away / Hidden remains secondary because it controls what others see. Adding someone never starts location sharing.
- **Activity:** show recorded events and receipts with their status and timing; keep the empty state calm and useful.
- **You:** focus on profile picture, a visible and copyable personal handle, an explicit “Help people find me” toggle, membership, My location, appearance, and account. Explain that discovery lets people with the complete phone number find the handle, and that the profile picture can appear in exact handle or phone matches. Discovery starts off for existing accounts. Turning it off prevents future phone matches and unconnected picture previews; an active connection still authorizes the existing picture view. Tap the avatar with its camera badge to open the shared picture picker. Keep Terms, Privacy, and Support links fixed at the bottom of the screen. My location opens a detail screen for device permission and Home place, while sharing status controls live in Sharing. Appearance is a compact System / Light / Dark preference saved on this device, with System as the default.
- **Profile pictures:** offer 11 sleepy-animal illustrated choices in a horizontal carousel, with no visible names; expose each choice's name to accessibility. Keep the selected picture large and centered in the preview. Put Photos, Camera, and Remove picture in a native menu attached to the preview avatar; do not add a separate photo section. Use a compact sheet that can expand when needed. Stage changes until Save and disable editing while a save is running. A picture appears in exact discovery matches only when the account has opted in; otherwise it remains visible to active connected people. Search previews are small inline thumbnails, never public URLs. Removing a picture falls back to initials. Preserve initials for missing or failed photo loads. The selected art direction is **hand-drawn doodle**: purposeful slightly uneven navy pen strokes, matte muted fills, subtle asymmetry, and one sleeping animal on a quiet background. Avoid redundant contours and fur hatching. Each subject must read clearly inside a 44 pt circular crop. No text, border, or glossy depth. Sleepiness is identity art and must never indicate whether someone is offline, safe, or sharing.

  The 11 selected sleepy-animal illustrations are the current preset catalog in `apps/trust-ios/Resources/Assets.xcassets`; it includes Siamese, Ragdoll, and British Shorthair cats. Keep legacy preset IDs readable for saved profiles even when the picker no longer offers them. New IDs must be accepted by the API before they are offered in the app. In the offline demo, preset edits last for the current session and photo actions are disabled with an explanation; the live app uses authenticated save behavior.
- **Plus:** use StoreKit's subscription products for price and period, preserve restore and policy links, and show purchase or restore errors clearly.

## Duo layout target

The closed Duo keeps the compact phone experience. When open, the map stays on the left and people/detail navigation stays on the right. The adaptive People layout and width-aware Map route retain one navigation stack across layout changes. Keep profile and sharing controls legible in both appearances and at larger text sizes; device-specific test evidence belongs in `FEATURE-E2E-PLAN.md`.

## Product language

Sharing is a per-person choice. Avoid implying that Trust guarantees delivery of push notifications or SMS beyond the verification flow. Describe map, presence, and activity only as implemented; distinguish a one-time snapshot from live sharing.
