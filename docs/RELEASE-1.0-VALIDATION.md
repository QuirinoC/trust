## Question this plan answers

Can a person complete every shipped Trust behavior, end to end, with the consent and privacy rules in `DESIGN.md` and `SCREENS.md`, on the current source?

Public App Review is a separate gate. Simulator evidence cannot close carrier SMS, Apple's live AppTransaction service, physical background location, APNs presentation, or a real StoreKit purchase. Those rows stay open until a physical release candidate is exercised. They are listed so they are not mistaken for passing.

## Scoring rules

1. **One scenario, one score.** A local API with phone verification skipped can score Add someone, Sharing, or Look. It scores zero for phone verification, carrier delivery, or “onboarding is complete.”
2. **The assertion is the score.** If the test does not check the server and the visible UI for that behavior, the row stays open.
3. **Development OTP scores the phone UI and the API challenge.** It does not score Twilio, a carrier, HELP, or STOP.
4. **Memory scores product behavior.** PostgreSQL on loopback scores that the same behavior survives the real schema and migrator. Either store is valid for its own row.
5. **The DEBUG demo scores local interaction and copy.** It does not score consent, discovery, or location on the API.
6. **`reviewUnlock` scores the History and Always UI after an entitlement exists.** It does not score StoreKit purchase, restore, renewal, expiry, or refund.
7. **Simulator GPS and a visible Always permission score the Home UI and server marker.** They do not score physical background execution.
8. **A fault-proxy pass scores the race it injects.** It does not replace the happy-path row.
9. **Skips are zero.** A green `xcodebuild` that skipped a case is not evidence for that case.
10. **Light and dark, compact and Duo, and the accessibility text size used in the run** score only the screens that were actually shown.
